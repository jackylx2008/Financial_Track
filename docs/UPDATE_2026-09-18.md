# 2026-09-18 更新说明

## 1. 邮件账单流程拆分

- “邮件获取账单”只负责邮件采集、附件准备、六位数字密码破解和无密码原始文件归档，不再执行交易归一化。
- 附件破解默认启用，仍可在 GUI 中取消；破解结果仅按附件文件名保存到本机专用密码文件，不显示或提交真实密码。
- 成功读取的原始附件按机构写入 `raw_data/bank/<银行名称>/`。
- 在 `raw_data/bank/bank_information_summary.html` 汇总已获取的银行、文件数量、文件类型和日期范围。

## 2. 邮件数据归一化

- “邮件数据归一化”成为第二个选项卡，独立读取 `raw_data` 中的邮件正文和已解密附件。
- 第一步默认只运行确定性解析器，整合可读取的 PDF、Excel、CSV 和邮件正文，不主动检查本地 AI。
- 继续执行交易过滤、去重和来源追溯，生成质量报告以及完整人工审核 HTML。
- 审核 HTML 保留机构、月份、方向、金额、账户全名、商户全名、摘要和来源等字段，并支持筛选。
- 不生成脱敏样本页。

## 3. 未自动提取文件

- 自动解析未获得交易的附件写入：

  `processed_data/normalized/email_normalization_unresolved.json`

- “邮件数据归一化”页面右侧显示机构、文件类型、文件路径和未提取原因。
- 工作流成功结束后自动刷新列表，也可以人工点击“刷新列表”。
- 页面提供“打开审核 HTML”按钮，直接查看：

  `processed_data/normalized/bank_transactions_full_review.html`

## 4. 按需本地 AI/OCR

- “对未识别 PDF 使用本地 AI/OCR”默认关闭，确保第一步只做自动归一化。
- 用户主动勾选后，仅对确定性解析无结果的文档调用本地 AI。
- PDF 回退直接将页面渲染为图片并调用视觉接口，避免无效的重复文本请求。
- AI 服务只在实际调用时检查，不执行日常心跳。

## 5. 配置与依赖

- `financial_document_ai_fallback` 增加 OCR 开关、最大页数和渲染分辨率配置。

- `common.env`、密码文件、日志、原始数据和处理结果继续由 Git 忽略。
