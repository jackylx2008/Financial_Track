# 2026-09-17 项目更新说明

本次更新完成了邮件账单采集、银行交易解析、人工 HTML 审核和桌面 GUI 的一轮整合。项目仍以本机个人使用为目标，原始邮件、附件、密码、日志及处理结果均保留在 Git 忽略范围内。

## 1. 邮件账单采集

- 支持在 GUI 中按起止日期获取 126 邮箱账单，默认起始日期为 `2015-01-01`。
- 支持用户主动选择“扫描邮箱全部历史邮件”；启用后忽略日期和邮件数量限制。
- 邮箱目录不再由 GUI 修改，统一使用配置中的 `INBOX`。
- 邮件、附件清单、解压目录和归一化目录均使用配置或 CLI 默认路径。
- GUI 首个页签只执行邮件采集、附件准备、密码处理和附件提取，原始资料统一保存在 `raw_data/`。

## 2. 附件密码与失败处理

- `common.env` 仅通过 `FINANCIAL_ATTACHMENT_PASSWORD_ENV_FILE` 配置密码文件路径。
- ZIP/PDF 实际密码继续保存在该路径对应的专用 env 文件中，可按默认、银行、文件名、文件名模式或文件类型配置。
- GUI 不展示、不保存附件密码，命令预览和日志也不输出真实密码。
- 无法正确解压的 ZIP 或无法读取的 PDF 不再导致整批任务退出；其他附件和后续阶段继续执行，流程末尾只汇总附件名称、收件日期和邮件标题。
- 精简失败清单继续写入 `attachment_extract_failures.md`，仅保留附件名称、收件日期和邮件标题，便于人工定位后补充密码。

## 3. 银行交易解析与质量控制

- 增加工商银行、招商银行和建设银行邮件正文解析规则，并保留通用银行文本解析回退。
- 支持从邮件正文、PDF、Excel/XLSX、CSV 以及 ZIP 内文件提取交易信息。
- 统一交易字段包括机构、交易日期、入账日期、金额、收支方向、账户、账户尾号、商户、币种、摘要和来源定位。
- 增加重复交易合并和来源追溯，保留合并前的来源记录。
- 过滤账单合计、余额、额度、本期应还等非交易金额及低可信候选。
- 生成交易质量报告，统计解析、过滤、重复合并和异常情况。

## 4. HTML 人工审核

- 生成完整、未脱敏的银行交易 HTML 审核集，仅保存于被 Git 忽略的 `processed_data/`。
- 每条记录展示机构、月份、方向、具体金额、账户全名、商户全名、摘要和来源；缺失字段显示横杠。
- 支持按机构、日期、方向、账户、商户和来源筛选。
- 金额筛选区间包括：0–5000、5000–10000、10000–20000、20000–30000、30000–40000。
- 已移除不适合当前单人使用场景的脱敏样本页。

## 5. 本地 AI 行为

- GUI 启动、空闲和配置重载时不再执行 AI 心跳、模型列表查询或测试对话。
- 状态栏仅显示配置中的模型和本机接口，并提示尚未检测。
- 只有确定性解析器无法稳定处理文档、实际需要 AI 回退时，才检查本地 AI 服务并调用模型。
- PDF 文本仍无法解析时，可将页面渲染为图片并通过本地视觉接口直接 OCR；OCR 页数和分辨率由配置控制。
- 已用本机模型实测交通银行 PDF 视觉 OCR：单份 4 页文档成功返回 52 条交易；正式批处理不再先发起冗余的文本 AI 请求。
- API Key 继续从被 Git 忽略的 `common.env` 获取，不写入代码、示例或日志。

## 6. GUI 与全局配置

- 首个页签由“邮件/PDF 对账”调整为“邮件获取账单”。
- 第二个页签新增“邮件数据归一化”，第一步负责自动解析、质量报告和人工审核 HTML；右侧展示未自动提取文件，本地 AI/OCR 默认关闭并按需启用。
- 邮件页参数收敛为检查起始日期、检查结束日期、扫描全部历史和“破解邮件附件”；破解选项默认勾选。
- 删除独立的“暴力破解邮件附件”页，邮件完整流程直接用本地 GPU 对密码错误的 ZIP/PDF 枚举 6 位数字密码。
- 暴力破解固定使用 Hashcat GPU 设备、`000000–999999` 范围和失败附件清单，不在界面或日志中显示真实密码。
- 邮件工作流的主配置文件选择器迁移到“全局配置”页。
- 全局配置页支持浏览、重新加载和检查 YAML 配置；任务运行期间禁止修改。
- 所有耗时工作流继续通过后台子进程执行，并共享实时日志、取消控制、进度和耗时状态。
- GUI 使用系统主题提供的说明文字颜色，适配 macOS 自动深色模式；执行按钮使用统一系统字体，日志字号增加一级。
- GUI 日志同步写入项目根目录 `logs/main.log`，工作流子进程继续写入各自的入口日志。

## 7. 配置与输出位置

- 主配置：`config.yaml`
- 本机环境与凭据：`common.env`（不提交）
- 附件密码文件：由 `FINANCIAL_ATTACHMENT_PASSWORD_ENV_FILE` 指定（不提交）
- 邮件原始数据：`raw_data/financial_email/`（不提交）
- 解密后的银行原始数据：`raw_data/bank/<银行名称>/`（不提交）
- 银行信息汇总：`raw_data/bank/bank_information_summary.html`（不提交）
- 归一化数据和 HTML 审核集：`processed_data/normalized/`（不提交）
- 运行日志：`logs/`（不提交）

## 9. 邮件采集与 GUI 增量调整

- 邮件初判范围扩展到发件人、主题、正文和附件名称；仅财务相关邮件保存 EML、正文和附件。
- 在 `raw_data/financial_email/` 生成 `financial_email_review.html` 和对应 JSON，列出本次受检的全部邮件，支持搜索及按判断结果筛选。
- 邮件页说明文字增大并加粗，颜色跟随 macOS 系统主题；“开始执行”按钮恢复统一系统字体，底部日志字号增加一级。
- GUI 通过根目录 `logging_config.py` 初始化日志，界面实时输出同步保存到 `logs/main.log`；邮件子进程继续写入 `logs/financial_email_bot.log`。
- ZIP/PDF 密码不匹配或单个附件异常时继续处理剩余附件及后续阶段；失败汇总只显示附件名称、收件日期和邮件标题。
- WinZip AES 附件在标准库不支持时继续尝试 `pyzipper`，避免过早结束候选密码处理。

## 10. 邮件获取与 GPU 附件破解合并

- 独立破解页签已删除；“邮件获取账单”页中的“破解邮件附件”默认勾选，只处理最新清单中状态为 `password_failed` 的 PDF/ZIP。
- 第一个页签按“邮件采集 → 附件准备 → 初次提取并生成失败清单 → GPU 破解 → 再次提取”运行，到 `raw_data` 原始资料为止。
- 交易提取与审核移至第二个“邮件数据归一化”页签，两个阶段可独立重复执行。
- 破解范围固定为六位数字 `000000–999999`，关闭候选词典和内置 CPU 数字枚举，并使用 Hashcat `-D 2` 限定 GPU 设备。
- 破解成功密码仅按附件文件名写入 `FINANCIAL_ATTACHMENT_PASSWORD_ENV_FILE` 指向的本地文件，界面、日志和 Git 均不展示明文密码。
- 解密/解压后的无密码文件按银行写入 `raw_data/bank/`，并生成 `bank_information_summary.html` 汇总已获取银行、附件数量、类型和日期范围。
- `failed` 模式以最新失败清单为准：不会被旧的错误密码记录跳过，清单为空时也不会回退到全部加密附件。
- 已使用本机真实失败附件完成端到端验证：13 个目标全部破解成功；重新执行附件提取后，共 22 个附件全部成功，失败数为 0。
- 合并流程再次从邮箱完成真实验证：新发现的 9 个缺失密码附件全部由 GPU 破解；最终 22 个附件全部提取成功，按工商、建设、交通银行归档的 22 个 PDF 均已确认可读取且不再加密。
- 本机 Hashcat、zip2john、pdf2john 和 Perl 路径检查通过；完整自动化测试增至 73 项。
