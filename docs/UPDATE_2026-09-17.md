# 2026-09-17 项目更新说明

本次更新完成了邮件账单采集、银行交易解析、人工 HTML 审核和桌面 GUI 的一轮整合。项目仍以本机个人使用为目标，原始邮件、附件、密码、日志及处理结果均保留在 Git 忽略范围内。

## 1. 邮件账单采集

- 支持在 GUI 中按起止日期获取 126 邮箱账单，默认起始日期为 `2015-01-01`。
- 支持用户主动选择“扫描邮箱全部历史邮件”；启用后忽略日期和邮件数量限制。
- 邮箱目录不再由 GUI 修改，统一使用配置中的 `INBOX`。
- 邮件、附件清单、解压目录和归一化目录均使用配置或 CLI 默认路径。
- GUI 固定执行邮件采集、附件准备、密码处理、附件提取和交易归一化完整流程。

## 2. 附件密码与失败处理

- `common.env` 仅通过 `FINANCIAL_ATTACHMENT_PASSWORD_ENV_FILE` 配置密码文件路径。
- ZIP/PDF 实际密码继续保存在该路径对应的专用 env 文件中，可按默认、银行、文件名、文件名模式或文件类型配置。
- GUI 不展示、不保存附件密码，命令预览和日志也不输出真实密码。
- 无法正确解压的 ZIP 或无法读取的 PDF 会在共享日志区显示警告，包含附件类型、状态、文件路径和失败原因。
- 完整失败记录继续写入 `attachment_extract_failures.md`，便于后续补充密码或人工处理。

## 3. 银行交易解析与质量控制

- 增加工商银行、招商银行和建设银行邮件正文解析规则，并保留通用银行文本解析回退。
- 支持从邮件正文、PDF、Excel/XLSX、CSV 以及 ZIP 内文件提取交易信息。
- 统一交易字段包括机构、交易日期、入账日期、金额、收支方向、账户、账户尾号、商户、币种、摘要和来源定位。
- 增加重复交易合并和来源追溯，保留合并前的来源记录。
- 过滤账单合计、余额、额度、本期应还等非交易金额及低可信候选。
- 生成交易质量报告，统计解析、过滤、重复合并和异常情况。

## 4. HTML 人工审核

- 生成完整、未脱敏的银行交易 HTML 审核集，仅保存于被 Git 忽略的 `processed_data/`。
- 每条记录展示机构、月份、方向、具体金额、账户全名、商户全名、摘要和来源；缺失字段显示横杠。
- 支持按机构、日期、方向、账户、商户和来源筛选。
- 金额筛选区间包括：0–5000、5000–10000、10000–20000、20000–30000、30000–40000。
- 已移除不适合当前单人使用场景的脱敏样本页。

## 5. 本地 AI 行为

- GUI 启动、空闲和配置重载时不再执行 AI 心跳、模型列表查询或测试对话。
- 状态栏仅显示配置中的模型和本机接口，并提示尚未检测。
- 只有确定性解析器无法稳定处理文档、实际需要 AI 回退时，才检查本地 AI 服务并调用模型。
- API Key 继续从被 Git 忽略的 `common.env` 获取，不写入代码、示例或日志。

## 6. GUI 与全局配置

- 首个页签由“邮件/PDF 对账”调整为“邮件获取账单”。
- 邮件页参数收敛为检查起始日期、检查结束日期、扫描全部历史和跳过密码破解。
- 原独立附件破解页合并到邮件完整处理流程。
- 邮件工作流的主配置文件选择器迁移到“全局配置”页。
- 全局配置页支持浏览、重新加载和检查 YAML 配置；任务运行期间禁止修改。
- 所有耗时工作流继续通过后台子进程执行，并共享实时日志、取消控制、进度和耗时状态。

## 7. 配置与输出位置

- 主配置：`config.yaml`
- 本机环境与凭据：`common.env`（不提交）
- 附件密码文件：由 `FINANCIAL_ATTACHMENT_PASSWORD_ENV_FILE` 指定（不提交）
- 邮件原始数据：`raw_data/financial_email/`（不提交）
- 归一化数据和 HTML 审核集：`processed_data/normalized/`（不提交）
- 运行日志：`logs/`（不提交）
