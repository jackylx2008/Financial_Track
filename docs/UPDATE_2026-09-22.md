# 2026-09-22 更新记录

## 银行告警分类调整

- 交通银行人工审核通过的借记卡 PDF 交易表不提供本方账号或卡号；521 条流水不再产生
  `missing_account_tail` 系统性告警，原始 PDF 哈希、页码和表格行定位继续保留。
- 工商银行信用卡打印流水与月度 EML 唯一匹配后，PDF 单元格换行造成的商户空格差异，以及打印流水
  “对方户名”与邮件账单“商户/交易场所”的来源语义差异，不再产生 `conflict_merchant` 或
  `conflict_counterparty` 告警；两个来源的原始字段和定位仍完整保留。
- 建设银行及工商银行借记卡中余额连续变化但被合并的记录不自动修改，继续保留冲突告警，
  等待人工确认后再调整去重结果。
- 人工确认光大银行官方 Excel 第 450、451 行是两笔独立的 50,000 元入账：时间、金额和对方相同，
  但余额连续增加且摘要参考号不同。光大官方 Excel 现以“来源文件 + 工作表 + 行号”作为权威交易身份，
  相邻数据行不再被通用去重规则合并。
- 工商银行、交通银行已确认 PDF 仍只读取人工审核缓存，本轮规则调整不触发本地 AI/OCR。
- 工商银行借记卡中同一时刻、同方向、同金额、同交易双方但交易后余额不同的相邻流水不再合并。该规则覆盖
  2018-09-25 收入 83 元（PDF 第 6 页第 17、18 行）和 2025-09-21 支出 42 元（PDF 第 42 页
  第 20、21 行），两组均分别保留为两笔交易。

## 审核页 PDF 免密链接

- 银行审核 HTML 不再同时展示解密副本和邮箱中的原始加密 PDF；存在附件提取后的可读副本时，只显示明确标记为
  “免密PDF”的链接，避免由本机默认 PDF 程序再次弹出密码输入框。
- 生成链接前会验证 PDF 确实无需密码；加密 PDF 不再生成可点击链接。原始加密附件的路径、文件 SHA-256 和
  邮件来源仍保留在归一化 JSON/JSONL 中，追溯链路不受影响。
- ZIP 文件无条件不生成审核链接；ZIP 已成功解压时，直接链接对应的 Excel、CSV 或免密 PDF，并在页面标为
  “解压文件”或“免密PDF”。
- 使用现有银行归一化结果重建审核页；余额去重规则调整后当前共 21,620 条银行交易。页面重建没有重新扫描
  PDF，也没有调用本地 AI/OCR。

## 银行审核筛选与金额汇总

- 新增工商银行信用卡“主卡/副卡”、年度和月度筛选，并继续支持币种筛选。年度、月度选项根据实际交易日期
  动态生成，并可与日期范围及其他筛选条件组合使用。
- 页面底部根据当前全部筛选条件实时汇总，按币种分别显示笔数、收入金额和支出金额；不再显示收入与支出的
  合计金额，不同币种也不直接混加。
- 人民币、`RMB`、人民币元及人民币符号统一归一化为官方币种代码 `CNY`，不再在币种筛选和金额汇总中拆成多行；
  审核页面向用户显示为“人民币”。

## 银行流水清单界面精简

- GUI 和 HTML 的“银行交易完整人工审核集”统一更名为“个人银行交易完整流水清单”；HTML 标题根据实际读取到的
  交易日期自动附加“最早日期 至 最新日期”，无需人工维护。
- 主表不再单独显示商户/对方全名、对方账号、摘要和渠道四列，对应完整数据仍嵌入页面，可通过顶部全文搜索检索。
- 顶部新增交易金额排序按钮，默认保持原有顺序；点击后按金额从大到小排列当前筛选结果，再次点击恢复默认顺序。
- 本次只使用既有归一化数据重建 HTML，没有扫描 PDF，也没有调用本地 AI/OCR。

## 币种中文显示

- 银行及支付宝/微信审核页中的币种筛选、流水明细和金额汇总统一显示中文名称：`CNY` 显示为人民币、
  `GBP` 显示为英镑、`JPY` 显示为日元、`SGD` 显示为新加坡元、`USD` 显示为美元。
- 原始数据中的“日元、英镑、新加坡元、美元”等中文写法会先归一化到对应 ISO 4217 代码，避免同一币种被拆分统计；
  人工审核界面再转换为中文。底层代码与哈希所用的标准币种代码不变。

## 信用卡取消与退款配对

- 信用卡/贷记卡流水按机构、卡片、币种和金额进行一对一匹配；同金额支出之后在配置窗口内出现收入时，标记为
  “交易取消退款”。窗口由 `config.yaml` 的
  `bank_transaction_review.credit_card_refund_window_days` 控制，默认 31 天；借记卡和超过时间范围的记录不参与匹配。
- 配对后的原支出和退款收入仍保留为两条可追溯流水，整行所有单元格显示半透明斜线阴影；底部筛选笔数仍计入两条记录，
  但收入金额与支出金额汇总均排除这组取消交易。

## 信用卡交易场所

- 银行流水主表新增“交易场所”列。信用卡/贷记卡优先读取原始账单的交易场所、交易地点或商户名称，缺失时
  使用归一化商户名称。
- 借记卡没有交易场所，该列固定显示短横线“—”；取消退款的整行斜线阴影同时覆盖新增列。

## 重复信用卡信息源人工取舍

- 新增本机来源取舍清单 `raw_data/bank_source_selection.local.txt`。人工确认两套邮件/PDF交易内容完全一致后，
  可登记被排除来源的唯一目录或文件标识；归一化在去重前排除该来源，只让指定权威邮件及对应PDF参与合并。
- 清单可同时保存权威来源、被排除邮件及PDF的路径和完整SHA-256；原文件不删除。`raw_data/` 已被 Git 忽略，
  个人文件名、哈希和人工决定不会提交到仓库。
- 清单路径由 `bank_transaction_review.source_selection_file` 配置；清单不存在时保持原行为。
