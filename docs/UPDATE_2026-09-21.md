# 2026-09-21 更新记录

## 审核集分流

- `bank_transactions_full_review.html` 现在只包含工商、交通、建设、招商、光大等银行流水。
- 银行完整审核页在全文搜索旁新增“是否有告警”筛选，可查看全部、有告警或无告警记录，并与其他条件联动。
- 消费入口打开的购物订单审核页和支付宝/微信支付审核页也提供相同的告警筛选。
- 光大银行独立 Excel 原本不含本方账号或卡号；该来源不再因账户尾号为空逐条产生
  `missing_account_tail` 告警，其他来源的尾号质量检查保持不变。
- 工商银行 14 份、交通银行 7 份 PDF 已按 SHA-256 记录人工审核通过状态；后续归一化直接读取人工确认的
  PDF 表格缓存，禁止把这些文件重新加入本地 AI/OCR 队列。缓存异常时仅列入未解析清单，重新 OCR 前需人工确认。
- 工商银行信用卡 EML 中逐笔出现的主卡/副卡后四位现在同时补入归一化账户尾号，并继续独立保存交易卡尾号
  和主副卡角色；银行审核 HTML 将该列明确显示为“卡号后4位”，尾号筛选同时匹配账户尾号和交易卡尾号。
- 新增 `payment_transactions_full_review.html`，统一审核支付宝和微信支付流水。
- GUI“邮件数据归一化”页分别提供银行审核页和支付审核页入口。
- 统一 `bank_transactions.jsonl/json` 继续保留全部资金流水，供跨来源链路计算使用。

## 逐条流水 SHA-256

- 每个原始邮件候选、PDF 页/行、Excel/CSV 行、截图或订单来源记录增加完整
  `source_record_sha256`。
- 每条银行、支付宝、微信及订单归一化记录增加唯一 64 位 `flow_hash_sha256`；同时按类型保存
  `transaction_hash_sha256`、`order_hash_sha256`。
- 每条统一财务事实增加 `financial_transaction_hash_sha256` 和 `flow_hash_sha256`。
- 每条关系记录增加 `link_hash_sha256`；原有短 ID 保留用于兼容，不再作为完整性或唯一性凭据。
- 哈希字段不参与业务版本指纹，新增哈希不会被误判为交易内容修正。

## 支付链路基础

- 支付账户流水在财务事实层明确标记为 `payment_account_transaction`，与真实银行流水区分。
- 新增 `payment_chain_links.jsonl/json`，保存订单到支付流水以及支付宝/微信到银行卡的关系。
- 支付账户到银行卡采用保守关联：金额完全相同、日期相差不超过三天、银行侧支付渠道与支付宝或微信一致。
- 同一支付流水存在多个银行卡候选时仅标记为 `candidate`，不自动确定唯一扣款卡。
- 金额和渠道建立索引后再匹配，避免全量记录两两扫描。

## 审核来源文件打开方式

- 银行、支付、购物订单和 PDF 表格审核页不再把 `file://` 地址交给浏览器处理。
- 所有来源链接统一通过 GUI 启动的本机回环桥接，并在 Windows 上明确调用系统注册的 `open` 文件关联；
  PDF、图片和 EML 因而分别交给台式机设置的默认程序。
- 同一流水分别列出来源文件、原始附件、原始 EML、原始图片和邮件正文，避免只能打开中间解析文件。
- Windows 没有为某种扩展名配置默认程序时，页面显示 Shell 错误码，不再错误提示“已打开”。

## PDF 双栏人工审核程序

- 根目录新增独立入口 `pdf_ocr_review_app.py`，与主数据采集、归一化和统计流程隔离。
- 默认以已完成 OCR 核验的交通银行 PDF 为案例；左侧渲染原始 PDF 页面，右侧按原页面坐标显示
  同一哈希缓存中的识别表格。
- 左右画布共用纵向滚动位置，鼠标滚轮和纵向滚动条会同时移动两侧；两侧保留独立横向滚动条。
- 支持机构/PDF/页码选择、100%-200% 缩放、Windows 默认程序打开原 PDF，以及载入其他已有哈希缓存的 PDF。
- 左右审核画布支持 `Ctrl + 鼠标滚轮` 按档位缩放，并在重新渲染后恢复当前纵向和横向审核位置。
- 按住 `Ctrl + 鼠标左键` 左右拖动任一审核画布时，两侧按相同页面比例同步横向移动，纵向位置保持不变；
  一侧先到达左右边界不会阻止另一侧继续移动，反向拖动也不产生空行程。
- 原始 PDF 默认显示比例由 125% 提高两档至 175%，改善左侧小字号账单的可读性。
- 右侧识别数据表格字体整体增加两个字号，页面坐标和左右同步滚动规则保持不变。
- PDF 首次进入审核程序时，以第一页 OCR 文字范围识别左右边框，并把裁剪后的内容宽度同时用于原页和识别表格。
- 裁边位置按完整 PDF SHA-256 缓存在根目录 `pdf_ocr_crop_positions.local.json`；同一哈希只识别一次，
  后续直接读取缓存，文件内容变化时才重新 OCR。该本地文件已加入 Git 忽略规则。
- 人工审核区新增“确认通过”按钮，点击后把当前页标记为“一致”并立即保存，不自动切换页面。
- 每页人工结论和备注单独写入 `processed_data/pdf_html_review/pdf_ocr_manual_review.json`，不修改识别缓存，
  不进入交易归一化或财务统计。

## 工商银行斜向水印过滤

- PDF 表格提取前按字符旋转矩阵过滤斜向文字；工商银行样例中正文为 0°、水印为 30°，不依赖易变化的灰度值。
- 表格线、图片、水平正文和垂直正文继续保留；缓存结构升级到版本 2，旧缓存自动失效并重建。
- OCR 核验忽略倾斜文本框，本地 AI 提示词禁止把水印、印章、二维码及防伪标记内容写入交易字段。
- 已重新处理 21 个银行 PDF，共 1381 页、35387 行；63 个首/中/末页 OCR 对照全部通过。
- 工商银行首组 185 页账单共 4618 条数据行，金额列中的换行水印碎片和字母水印碎片均为 0。

## 人工审核快捷入口

- 根目录新增 `open_bank_review.bat`，双击后使用 Windows 默认浏览器打开银行流水完整审核页。
- 根目录新增 `open_consumption_review.bat`，同时打开美团/拼多多/京东订单审核页和包含淘宝 CSV 流水的
  支付审核页，避免只打开订单页时遗漏淘宝记录。
- 两个入口均使用 `%~dp0` 相对路径定位，项目移动或盘符变化后仍有效；目标不存在时给出提示并返回失败状态。
- 根目录新增 `open_bank_review.command` 和 `open_consumption_review.command`，供 macOS 双击运行并使用
  系统默认浏览器打开相同审核页面。
- macOS 入口从脚本自身目录定位文件，不依赖 Windows 的 `D:\CloudStation` 或 macOS 的
  `~/SynologyDrive/` 目录名称；脚本固定使用 LF 换行，首次使用若受本机权限影响可手动运行 `chmod +x`。
